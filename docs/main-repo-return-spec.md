# מפרט החזרת הכרעות — הצד השני של הגשר

משלים את `main-repo-bridge-spec.md` (חובה לקרוא קודם). שם תואר המסלול הלוך:
כרטיס בריפו הראשי → דיון גישור בקונצנזוס. כאן מתואר המסלול חזור: **הכרעה
חתומה שנשמרת בשרת וחוזרת לכרטיס המקור** — לכל חברי הריקמה, לא רק למי שלחץ
על הקישור.

## הבעיה עם ההחזרה הקיימת

עד עכשיו ההחזרה חיה רק בפרמטר `negoBridge` שב-URL: מי שלחץ על "החזרת ההסכמה"
קיבל מילוי מוקדם של השדות — אבל ההכרעה עצמה לא נשמרה בשום מקום. חבר אחר שפתח
את הכרטיס לא ראה דבר, ורענון איבד את הקשר.

## הפתרון: `resolution` על ה-Negotiation

כשמתגבשת הסכמה, משתמש רשום "חותם" עליה ב-BridgeBar. החתימה:

1. שומרת JSON `resolution` על רשומת ה-Negotiation (ומסמנת `status: completed`).
2. הכרטיס בריפו הראשי שולף אותה לפי `(sourceType, sourceId)` — אותו מפתח של
   ה-find-or-create בהלוך — ומציג/ממלא אותה לכל החברים.
3. הקישור `negoBridge` ממשיך לעבוד כמילוי מוקדם מיידי; אחרי חתימה הוא נבנה
   מהתנאים החתומים, כך ששני הערוצים מציגים אותו דבר.

**האישור הסופי נשאר במנגנון ההצבעה הקיים** — ההכרעה מגבשת את ההצעה, לא עוקפת
את הקונצנזוס.

מבנה ה-`resolution` (נכתב על-ידי הקונצנזוס, נקרא על-ידי שני הצדדים):

```json
{
	"v": 1,
	"sourceType": "tosplit",
	"sourceId": "42",
	"positionId": "17",
	"heading": "נוסחת אמצע",
	"summary": "תיאור העמדה שנבחרה",
	"values": { "m:8": 120.5, "m:13": 79.5 },
	"terms": [
		{
			"key": "m:8",
			"label": "החלק של דנה",
			"kind": "number",
			"value": 120.5,
			"body": null,
			"stance": 50
		}
	],
	"decidedAt": "2026-07-02T10:00:00.000Z"
}
```

## מה צריך להוסיף בבקנד (Strapi) — הטבלה

| #   | תוספת                                     | איפה                       | סוג        | הערות                                                                                                                             |
| --- | ----------------------------------------- | -------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `resolution`                              | Content-Type `Negotiation` | JSON       | ההכרעה החתומה במבנה שלמעלה. השדה **היחיד** שחסר בסכמה.                                                                            |
| 2   | הרשאת `update` על Negotiation             | Roles → Authenticated      | permission | נדרש כדי ש-`43SetNegotiationResolution` ירוץ עם JWT של משתמש רשום. אין צורך בהרשאת service-token (ה-qid בכוונה לא ב-allow-lists). |
| 3   | (אם טרם) index על `sourceType`+`sourceId` | DB                         | index      | הומלץ כבר במפרט ההלוך; משרת גם את שליפת ההכרעה.                                                                                   |

**סדר פריסה:** קודם השדה ב-Strapi, אחר כך (או יחד) הקוד. שני ה-qids החדשים הם
qids חדשים ונפרדים — הקריאות הקיימות (`39GetNegotiation` וכו') לא נגעו, כך ששום
דבר לא נשבר אם השדה עוד לא קיים; רק פיצ'ר ההחזרה יחזיר שגיאה עד שיתווסף.

## qids חדשים (כבר ממומשים ב-`src/routes/api/send/qids.js` בריפו הראשי)

| qid                                | סוג      | arg                          | מי רשאי                                                                                                                          |
| ---------------------------------- | -------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `43SetNegotiationResolution`       | mutation | `{ id, resolution, status }` | רשומים בלבד (JWT). לא ב-`CONSENSUS_QIDS` ולא ב-allow-lists של הקונצנזוס — אין מסלול service-token.                               |
| `GetNegotiationResolutionBySource` | query    | `{ sourceType, sourceId }`   | רשומים בלבד (JWT), כמו `GetNegotiationBySource`. מחזיר את העדכני ביותר (limit 1) עם `id, resolution, status, shareToken, topic`. |

> מומלץ (כמו במפרט ההלוך): לאכוף בצד השרת שהמשתמש חבר בפרויקט של האובייקט,
> ושה-`creator` או משתתף הוא זה שחותם. כרגע Strapi אוכף רק "משתמש מחובר".

## הצד הצורך בריפו הראשי (ממומש)

- `src/lib/func/negoBridge.js` — `fetchBridgeResolution(sourceType, sourceId, fetch)`:
  שולף את ההכרעה + `negotiationId` (ללינק חזרה לדיון). מחזיר `null` בשקט אם אין.
- `negoPend.svelte` / `negoM.svelte` — אם אין פרמטר `negoBridge` ב-URL, הכרטיס
  שולף את ההכרעה השמורה וממלא מראש את שדות העריכה. המשתמש עדיין שולח ומצביע
  כרגיל.
- `lev/cards/haluka.svelte` — כרטיס החלוקה:
  - כפתור "🤝 דיון מעמיק" שפותח דיון גישור עם תנאי לכל חבר:
    `key: "m:<uid>"`, `label: "החלק של <שם>"`, `kind: number`,
    `original` = "מגיע" (החלק ההוגן), `proposed` = "בפועל" (אחרי ההעברות המוצעות).
    `sourceType: 'tosplit'`, `sourceId: tosplitId`.
  - באנר הכרעה: כשקיימת `resolution`, הכרטיס מציג את הערכים המוסכמים לכל חבר
    ולינק לדיון — וההצבעה (בעד/נגד) נשארת הערוץ הפורמלי.

## זרימה מלאה (דוגמת חלוקה)

```
כרטיס חלוקה ─🤝 דיון מעמיק→ consensus/negotiation/bridge?d=…
   │                              │ find-or-create לפי (tosplit, id)
   │                              ▼
   │                    דיון: היבט לכל חבר, טיעונים, נוסחת אמצע
   │                              │ ✅ חתימת ההכרעה (משתמש רשום)
   │                              ▼
   │                43SetNegotiationResolution → resolution על הרשומה
   ▼
פתיחת הכרטיס ע"י כל חבר → GetNegotiationResolutionBySource
   → באנר "הדיון הגיע להכרעה" עם הערכים המוסכמים → הצבעה רגילה
```
